# 掘金推广文

标题：我用 DeepSeek API 做了个 AI 合同审查工具，帮你避开合同里的坑（附完整实现）

## 背景

作为一个经常接外包的开发者，我踩过不少合同的坑。

最惨的一次：对方合同里写了"具体需求以甲方口头说明为准，甲方有权随时变更需求，乙方不得要求增加费用"。我没仔细看就签了，结果需求变了 5 次，白干了一个月，还不好意思说不。

从那以后我就想：能不能用 AI 帮我自动审查合同，把这些坑都标出来？

说干就干，用了一个周末，基于 DeepSeek API 做了个 AI 合同审查工具。

## 效果展示

输入一份合同，输出：

1. **合同类型判断**（服务合同/劳动合同/买卖合同/保密协议等）
2. **整体风险等级**（高/中/低）
3. **风险项列表**，每条包含：
   - 条款类型
   - 风险等级（高/中/低）
   - 原文摘录
   - 大白话解释（让非法律专业的人也能看懂）
   - 风险说明（这条有什么问题，可能导致什么后果）
   - 修改建议（具体怎么改，甚至给出可直接替换的条款文本）
4. **关键建议**（AI 给出的核心注意事项）

我故意写了一份埋了 10 几个坑的示例合同（在 examples/ 目录），测试效果还不错——识别出 17 个风险点（9高5中3低）。以下是几个典型案例的完整输出：

### 案例 1：验收标准甲方单方说了算

**原文摘录**：「如甲方认为项目未达到验收标准，有权拒绝支付任何费用，且乙方不得提出异议。」

**大白话解释**：甲方说不合格就不合格，说不给钱就不给钱，乙方连反对的权利都没有。

**风险说明**：这是最恶劣的霸王条款。甲方可以故意挑刺不验收，赖掉全部款项。「不得提出异议」剥夺了乙方的基本权利，虽可能因显失公平被法院撤销，但打官司耗时耗力。

**修改建议**：
> 验收标准以双方书面确认的《需求文档》为准。甲方应在收到乙方交付物后 10 个工作日内完成验收并出具书面意见。甲方逾期未提出书面异议的，视为验收合格。

### 案例 2：逾期违约金每日 5%（年化 1825%）

**原文摘录**：「乙方逾期交付的，每逾期一日，应向甲方支付项目总费用 5% 的违约金。」

**大白话解释**：项目总额 5 万，晚一天交付赔 2500 元，晚 20 天赔完整个项目款。

**风险说明**：每日 5% 的违约金年化利率 1825%，远超法律保护上限（目前 LPR 约 3.45%，4 倍约 13.8%）。法院大概率会调低，但甲方可以用这个条款施压，乙方心理压力巨大。

**修改建议**：
> 乙方逾期交付的，每逾期一日支付项目总费用 0.5‰ 的违约金（即每日 25 元），累计不超过项目总费用的 20%。逾期超过 30 日的，甲方有权解除合同。

### 案例 3：乙方已有技术被甲方无偿占有

**原文摘录**：「乙方在开发过程中使用的任何已有技术、代码、工具、框架，均视为乙方无偿授权甲方永久使用，甲方无需支付任何额外费用。」

**大白话解释**：你以前写的代码、用的 React/Vue/Spring 等开源框架、积累的工具类，全部白送给甲方。

**风险说明**：范围极宽。甲方以后可以拿着你的代码库去做别的项目，你还不能反对。如果你是做外包的，等于把自己多年积累的家底全送出去了。

**修改建议**：
> 项目定制开发的代码归甲方所有。乙方在开发过程中使用的开源组件、通用工具类、自有技术框架，其知识产权归原作者或乙方所有，甲方获得在本项目中的使用权。乙方有权在其他项目中使用其自有技术和通用代码。

### 案例 4：违约金严重不对等

**原文对比**：乙方逾期交付每日 5% vs 甲方逾期付款按「银行同期活期存款利率」（约 0.2%/年）

**风险说明**：相差 9000 倍。甲方可以放心拖欠款项，几乎没有成本；乙方晚一天交付就赔巨款。这种不对等条款在实践中很常见，但签之前完全可以谈判修改。

**修改建议**：甲方逾期付款的，每逾期一日按应付未付金额的 0.5‰ 支付违约金，与乙方违约责任对等。

以上仅为部分展示，完整审查包含 17 个风险点的详细分析。从测试效果看，AI 已经能识别出大部分常见的合同陷阱，并且给出的修改建议具体可操作，对于不懂法律的普通人来说，作为「签合同前的第一道防线」完全够用。

## 技术实现

### 整体架构

```
用户输入（文本/文件）
    ↓
FastAPI 后端
    ↓
合同文本预处理（长度检查、编码处理）
    ↓
构建审查 Prompt（系统提示词 + 用户合同 + 输出格式要求）
    ↓
调用 DeepSeek Chat API（response_format: json_object）
    ↓
解析返回的 JSON
    ↓
风险分级统计 + 排序
    ↓
返回前端展示
```

### 核心：Prompt 设计

这是整个工具最关键的部分。好的 Prompt 决定了审查质量。

我的系统提示词包含几个部分：

1. **角色设定**：15 年执业经验的资深合同审查律师，精通民法典合同编
2. **审查重点**：列出 13 类高风险条款类型（违约责任、争议解决、知识产权、保密、付款、期限终止、不可抗力、保证担保、竞业限制、数据保护、免责条款、主体签署）
3. **风险等级标准**：高/中/低的判定标准
4. **输出要求**：严格 JSON 格式，字段说明，至少 5 条最多 15 条风险

用户提示词则包含：
- 合同文本
- 明确的 JSON schema 要求
- 几个关键约束（原文必须真实存在、不要编造、优先识别高风险）

### 为什么选 DeepSeek

1. **便宜**：deepseek-chat 模型 1 元/百万 tokens，一份 5000 字的合同审查成本不到 1 分钱
2. **中文好**：对中文法律文本的理解能力不错
3. **支持 JSON 模式**：`response_format: {"type": "json_object"}` 保证输出是合法 JSON
4. **新用户有免费额度**：适合个人项目

### 前端

纯原生 HTML + CSS + JS，没有用任何框架。原因：
1. 项目小，不需要框架
2. 原生加载快，没有依赖
3. 方便部署，一个 FastAPI 服务全搞定

前端做了这些交互：
- Tab 切换（粘贴文本/上传文件）
- 拖拽上传
- 加载动画
- 风险卡片（按高/中/低排序，不同颜色标识）
- 响应式布局（手机也能用）

## 一些思考

### 这个工具的定位

这不是一个要取代律师的工具。它的定位是：
- **个人/小团队的合同初审工具**：签合同前先过一遍，把明显的坑标出来
- **法律意识普及工具**：大白话解释让非法律专业的人也能看懂合同
- **效率工具**：帮律师/法务做初筛，节省时间

重要合同还是建议找专业律师。

### 可以改进的地方

1. **支持 PDF/Word 上传**：目前只支持纯文本，后续可以加 python-docx 和 PyPDF2
2. **合同模板库**：提供各类标准合同模板，用户可以基于模板修改
3. **对比功能**：对比两份合同的差异
4. **历史记录**：保存审查历史（本地存储，不上云）
5. **多模型支持**：除了 DeepSeek，也支持 GPT、Claude、通义千问等
